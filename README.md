# krysha-kz

Ежедневный список квартир с [krisha.kz](https://krisha.kz) (Актау) и калькулятор маржи флиппинга.
Приложение: https://u-seed.github.io/krysha-kz/ (на телефоне: «Добавить на главный экран»).

## Как устроено
1. GitHub Actions каждый день в 08:00 (Актау) запускает `scraper/krysha_scraper.py`.
2. Парсер обходит выдачу по комнатам из `config.json`, определяет отделку
   (`draft` — черновая в карточке, `likely` — слова в описании, `renovated` — с ремонтом, `unknown` — не ясно),
   продавца (хозяин / специалист / компания / застройщик), мкр, ЖК, цену, историю цены.
3. Результат пишется в `data.json` (и `status.json` с итогом запуска), приложение читает их.

## Расчёт маржи
`затраты = цена покупки + ремонт + риелтор`, `налог = 10% × (ДКП продажи − ДКП покупки)`,
`маржа = цена продажи − затраты − налог`. Три сценария ДКП покупки:
по факту, завышен до цены продажи (налога нет), занижен (по умолчанию 5 млн).
Цена продажи: ручная → эталон (мкр + комнаты + площадь) → самая низкая цена похожей готовой квартиры в том же ЖК/доме/мкр.
Ремонт, риелтор, налог, эталоны меняются в приложении (⚙), хранятся на телефоне.

## Файлы
- `index.html`, `calc.js`, `sw.js`, `manifest.json` — приложение (PWA)
- `scraper/` — парсер и тесты: `python scraper/test_parse.py`, `node scraper/test_calc.js`
- `config.json` — какие комнаты собирать, паузы между запросами, включение догрузки описаний
- `.github/workflows/daily.yml` — расписание; запустить вручную: Actions → «Ежедневный сбор крыши» → Run workflow

## Правила, которые применяет парсер
**Какой мкр считать.** Адрес на крыше состоит из двух частей: «18-й мкр , Мкр. 29А Латифа» — мкр с карты (его часто ставят
неверно) и адрес, который ввёл продавец. Приоритет: **описание > адрес продавца > мкр с карты**. Ориентиры («рядом с 17 мкр»,
«напротив 16 мкр»), хвост адреса после « — » и всё, что написано после слова «обмен» в описании, мкр не меняют.
Если мкр исправлен, в карточке (раскрыть) видно: «Мкр исправлен: на карте крыши «18», в адресе продавца — 29А».
В `data.json` это поля `mo` (мкр с карты) и `mw` (`a` — из адреса, `d` — из описания).

**Исключённые ЖК.** Список регулярок в `config.json` → `exclude_zhk` (сейчас: Шахар Towers/Тауерс, Махаббат). Совпадение ищется
в поле ЖК и в тексте вида «ЖК <название>». Такие объявления вообще не попадают в `data.json`; сколько убрано — в `status.json`
(`excluded`). Добавить ещё один ЖК — дописать строку в список.

**Применить правила к уже собранным данным без сети:** `python scraper/krysha_scraper.py --reprocess`.

## Если сбор не работает
Приложение покажет красную плашку с причиной (из `status.json`). Самая вероятная причина — крыша блокирует
IP серверов GitHub. Тогда тот же скрипт запускается на своём ПК/VPS (`python scraper/krysha_scraper.py`,
затем `git push`), остальное не меняется. Образцы HTML для отладки лежат в артефакте запуска `debug-html`.
